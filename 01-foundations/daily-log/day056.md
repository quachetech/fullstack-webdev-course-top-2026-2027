### Cloning a Remote Repository

```bash
git clone git@github.com:username/git_test.git
cd git_test/
```

Cloned the `git_test` repository from GitHub using SSH. This created a local
copy of the remote repository inside the `repos` directory.

```bash
git remote -v
# origin  git@github.com:username/git_test.git (fetch)
# origin  git@github.com:username/git_test.git (push)
```

Verified the remote connection. `origin` is the default name Git assigns to
the remote repository it was cloned from. Both fetch and push point to the
same GitHub URL — confirmed the link between local and remote is working.

---

### First Commit — Creating and Staging a New File

```bash
touch hello_world.txt
git status
```

Created a new blank file. `git status` showed it as **untracked** — Git can
see it exists but is not yet tracking it.

```bash
git add hello_world.txt
git status
```

Staged the file. `git status` now showed it under **Changes to be committed**
as a new file — it has moved from the working tree into the staging area.

```bash
git commit -m "Add hello_world.txt"
# [main 2375xxx] Add hello_world.txt
# 1 file changed, 0 insertions(+), 0 deletions(-)
```

Committed the staged file. Git created a snapshot and assigned it a unique
commit hash (`2375xxx`).

```bash
git status
# Your branch is ahead of 'origin/main' by 1 commit.
# nothing to commit, working tree clean
```

Working tree is clean — nothing pending. But the branch is ahead of the remote
by 1 commit, meaning the snapshot exists locally but has not been pushed to
GitHub yet.

```bash
git log
```

Showed two commits in history:
- `2375xxx` — Add hello_world.txt (local, HEAD)
- `bd28xxx` — Initial commit (origin/main — the remote's current state)

The divergence between local and remote is visible here.

---

### Second Commit — Editing Files in VS Code

```bash
code .
```

Opened the entire repository in VS Code to edit `README.md` and
`hello_world.txt`.

```bash
git add README.md
git add .
git status
```

Staged changes. `git status` showed three items ready to commit:
- `.vscode/settings.json` — new file created automatically by VS Code
- `README.md` — modified
- `hello_world.txt` — modified

Note: `git add README.md` was run first, then `git add .` to catch everything
else including the VS Code settings file.

```bash
git commit -m "Edit README.md and hello_world.txt"
# [main 815exxx] Edit README.md and hello_world.txt
# 3 files changed, 7 insertions(+), 1 deletion(-)
```

Second commit created. Three files snapshotted together in one atomic commit.

```bash
git log
```

History now shows three commits:
- `815exxx` — Edit README.md and hello_world.txt (HEAD -> main)
- `2375xxx` — Add hello_world.txt
- `bd28xxx` — Initial commit (origin/main)

Local is now 2 commits ahead of remote.

---

### Pushing to GitHub

```bash
git push
# To github.com:quachetech/git_test.git
#    bd28xxx...815exxx  main -> main
```

Both local commits pushed to GitHub in one operation. Remote is now fully
synchronized with local.

```bash
git status
# Your branch is up to date with 'origin/main'.
# nothing to commit, working tree clean
```

Local and remote are in sync. Working tree is clean. The full cycle is
complete.

### Final Configuration

```bash
cd
git config --global core.editor "code --wait"
```

Configured VS Code as the default Git editor globally. The `--wait` flag tells
Git to pause and wait until the VS Code window is closed before continuing —
important for commit messages and other Git operations that open an editor.

## 🔄 The Full Git Workflow — Practiced Today

```
Create/Edit files (Working Tree)
        ↓
git add (Staging Area)
        ↓
git commit (Local Repository)
        ↓
git push (Remote Repository on GitHub)
```

Every stage was executed at least once in today's session. The workflow is no
longer just theory — it has muscle memory behind it now.

## 💡 Key Observations from Practice

**`git status` is your compass.** Running it after every action shows exactly
where files are in the workflow — untracked, staged, committed, or synced.
There is no reason to ever feel lost in a Git session if you check status
regularly.

**`git log` is your timeline.** It shows the full commit history with hashes,
authors, dates, and messages. The relationship between `HEAD -> main` (local)
and `origin/main` (remote) is visible here — you can see at a glance whether
local and remote are in sync or how far apart they are.

**VS Code creates its own files.** Opening a repo with `code .` generated a
`.vscode/settings.json` file automatically. This is worth knowing — `git add .`
will catch these files. For projects where you don't want editor config files
tracked, a `.gitignore` file handles that (coming in a future lesson).

**`git push` batches commits.** Two local commits were pushed to GitHub in a
single `git push` operation. Git sends everything the remote doesn't have yet
in one go.
