## 🌐 HTML & CSS Basics

### The Three Languages of the Web

Every webpage is built from three languages working in distinct layers:

**HTML — HyperText Markup Language (The Builder)**
Defines all the content and structure of a page. The raw data from which a
webpage is built.

**CSS — Cascading Style Sheets (The Artist)**
Adds styling to HTML elements — colors, fonts, spacing, layout. Makes content
visually presentable.

**JavaScript (The Wizard)**
Adds interactivity and dynamic behavior. Responds to user input and animates
the page.

```
JavaScript  →  Behavior      (what it does)
CSS         →  Presentation  (how it looks)
HTML        →  Structure     (what it is)
```

### Key Points

- HTML and CSS are **not programming languages**. They do not execute logic,
  run loops, or perform calculations. They are markup and styling languages
  concerned only with presenting information.
- Web browsers read and translate these three languages into the visual
  webpages users see and interact with.
- These languages are constantly evolving — new features and elements are
  added regularly as the web matures.
- Frontend web development is the practice of building the visible, interactive
  layer of a web product using these three tools.

## 🏷️ Elements & Tags

### What is an HTML Element?

An HTML element is a piece of content wrapped in opening and closing tags.
Tags are keywords enclosed in angle brackets `<>` that tell the browser what
type of content it is reading.

### Anatomy of an Element

```html
<p>I am a paragraph.</p>
```

| Part | Role |
|---|---|
| `<p>` | Opening tag — marks where the element begins |
| `I am a paragraph.` | Content — what is displayed |
| `</p>` | Closing tag — marks where the element ends |

The closing tag mirrors the opening tag with a forward slash `/` added before
the keyword.

### Why Tags Matter

Tags tell the browser how to interpret and format content. Using the correct
tag for the content it wraps is important for two reasons beyond visual
appearance:

- **SEO** — Search engines read tags to understand page structure and content
  hierarchy, which affects how pages are indexed and ranked.
- **Accessibility** — Assistive technologies like screen readers rely on
  correct HTML tags to navigate content for users who need them.

Using tags that accurately describe the meaning of their content is called
**semantic HTML**.

### Void Elements

Most elements wrap content between opening and closing tags. Void elements are
the exception — they have only an opening tag and contain no content.

```html
<img>    <!-- displays an image -->
<br>     <!-- inserts a line break -->
<hr>     <!-- inserts a horizontal rule -->
<input>  <!-- creates a form input field -->
```

Void elements are sometimes written with a self-closing slash:
```html
<br />
<img />
```

Browsers render both forms correctly, but current HTML standards consider the
trailing slash obsolete. Modern preferred syntax omits it:
```html
<br>
<img>
```

## 💡 Key Insights

**Separation of concerns is intentional.** HTML, CSS, and JavaScript are kept
in separate files and separate languages so each can be changed independently.
Restyling a page means editing CSS without touching HTML. Adding interactivity
means writing JavaScript without rewriting structure. This modularity is what
makes web development maintainable.

**Semantic HTML is a discipline, not an afterthought.** The tag chosen should
reflect the meaning of the content, not just how it should look. A heading is
a heading because it is marked with a heading tag — not because it appears
large and bold. The visual presentation follows the semantic choice.

**HTML has predefined tags.** You do not invent your own. Every tag exists
because it describes a specific type of content or structure. Learning HTML
means learning the vocabulary of these tags and when to use each one correctly.
