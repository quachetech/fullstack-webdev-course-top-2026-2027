## 🔧 Build Process — Four Iterations

### Iteration 1: Initial Structure

Cloned the repository from GitHub, opened in VS Code, and built the entry
point:

```bash
cd repos/
git clone git@github.com:quachetech/odin-recipes.git
cd odin-recipes/
code .
```

Created `index.html` with full boilerplate and a single `<h1>` heading:

```html
<h1>Odin Recipes</h1>
```

---

### Iteration 2: Recipe Pages

Created the `recipes/` directory and three individual recipe HTML files —
`pizza.html`, `rice.html`, and `cake.html` — each with boilerplate and an
`<h1>` heading for the recipe name.

Added relative links from `index.html` to each recipe page, wrapped in an
unordered list:

```html
<ul>
    <li><a href="recipes/pizza.html">BBQ Chicken Pizza</a></li>
    <li><a href="recipes/rice.html">Fried Rice</a></li>
    <li><a href="recipes/cake.html">Black Forest Cake</a></li>
</ul>
```

Added a back-navigation link to each recipe page:

```html
<a href="../index.html">Home</a>
```

The `../` climbs up one directory level from `recipes/` back to the project
root where `index.html` lives.

---

### Iteration 3: Recipe Page Content

Added full content to each recipe page following the same structure:

- **Image** — embedded using a relative path from the `images/` directory
- **Description** — `<h2>` heading followed by one or two paragraphs
- **Ingredients** — `<h2>` heading followed by an unordered `<ul>` list
- **Steps** — `<h2>` heading followed by an ordered `<ol>` list

Image example from `recipes/cake.html`:
```html
<img src="../images/black-forest-cake.webp"
     alt="Black Forest Cake"
     height="310" width="310">
```

The `../images/` path navigates up from `recipes/` to the root, then into
`images/` — the same positional path logic practiced in the Links & Images
lesson.

## 💡 Key Observations

**Atomic commits in real practice.** Every distinct action — adding a file,
adding an image, adding content, adding a link — was committed separately.
The commit history reads like a build journal. Anyone cloning this repo can
follow exactly how the project was constructed step by step.

**Commit message conventions applied.** Messages follow the imperative mood
with a consistent prefix pattern (`HTML:`, `Doc:`, `Init:`, `Add`) that
makes the type of change immediately identifiable at a glance in `git log`.
This is the seven-rules standard from Day 76 applied to a real project.

**Relative paths across directory depths.** Images in `recipes/` pages all
used `../images/filename` — climbing up from `recipes/` to root before
reaching `images/`. The same positional logic from the Links & Images
practical, applied across three files.

**`git staus` typo caught by Git itself.** Git returned a helpful suggestion:
"The most similar command is status." A small reminder that the terminal is
unforgiving with spelling but informative when it catches the error.

**16 commits pushed in one `git push`.** All local commits accumulated
during the build session were pushed to the remote in a single operation.
Git sent everything the remote didn't have yet in one batch.
